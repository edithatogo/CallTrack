## Review finding and fix

### High — ComposeView had no lifecycle owner in the settings Activity

`AutomaticSettingsActivity` extended platform `Activity`, so Compose could not
resolve `ViewTreeLifecycleOwner` when attaching the lifecycle-disposed
ComposeViews. The host test crashed before rendering. The Activity now extends
AndroidX `ComponentActivity`, declared as a direct runtime dependency, which
supplies the required lifecycle ownership; the test rerun passed. Compose content
is installed only after `setContentView` attaches the view tree. Eight newly
required lifecycle/AndroidX metadata entries were independently checked against
canonical Google Maven bytes and added to the strict checksum policy. Existing
explicit permission callbacks and action ownership remain in place.

### Medium — standalone Compose instrumentation host was absent

The first component test launch failed because the androidTest manifest omitted
the `ComponentActivity` host. A test-only manifest declaration was added; the
rendered component test then passed. No production manifest entry was added for
the test host.

### Medium — Conductor integrity checks rejected the scoped development deferral

The repository verifier treated Track14's in-progress status as proof that
Tracks5–6 were complete, even though the documented authorization is limited to
local development. Track14 now points to its scoped deferral record. The
verifier permits only stage3's local work to proceed and leaves that stage
unresolved, so Track15 remains blocked. The fault suite includes a negative
check proving this scoped deferral does not unlock shared core.
The verifier also rejects completing Track14 while the scoped deferral remains,
and constrains its document path to the Track14 folder.
