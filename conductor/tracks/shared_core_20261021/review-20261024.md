# Review Report: Track 15 KMP shared core implementation

## Summary

The bounded common call-type selection and half-open time-range rules preserve
the existing Android facade and pass JVM/Android local checks; Track 15 remains
open until macOS Kotlin/Native acceptance and later preservation checks pass.

- [x] **Plan Compliance**: Partial — the approved portable selection/range slice is implemented; macOS Native and full cross-target preservation acceptance remain pending.
- [x] **Style Compliance**: Pass — ktfmt0.59 and `git diff --check` pass.

## Review notes

- The Java-visible `CallSelection` constructor, fields and methods remain in the
  Android app. The existing wrapper continues to validate the range before
  dereferencing a nullable source record, preserving the former failure order
  and exception message.
- Common code uses no platform APIs, storage, side effects or extra runtime
  library. The Android adapter still supplies the raw numeric CallLog type.
- `gradle/verification-metadata.xml` retains its previous entries and adds only
  12 compiler/test artifacts whose bytes match Maven Central. The verified test
  libraries declare Apache-2.0 in their POMs.
- A first Conductor test run exposed that an old synthetic “no Track 15
  deferral” case inherited the new metadata field. The fixture now removes that
  field explicitly. The added scoped-deferral test also confirms Track 16
  remains blocked and that a scoped deferral cannot complete Track 15.
- No production signatures, fingerprints, schemas, namespaces, receipts, ledger
  or writer ownership changed. No finding requires another production-code fix.

## Decision

Accept the bounded implementation slice with Track 15 still in progress and
`production_adopted=false`. The macOS arm64 Kotlin/Native test and artifact gate
requires a selected full Xcode and Apple SDK; the current host has Command Line
Tools only. Track 14's remaining Compose screens and acceptance still block
Track 16. The Track 15 scoped deferral does not resolve either gate.
